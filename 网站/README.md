# 时之笛 · 存档工坊（后端处理版）

这是 OOT SW2SE 的网页入口，桌面版不受影响。浏览器只负责交互和文件传输，Node.js 服务端复用仓库根目录 `editor.html` 的解析、校验和补丁生成算法。网页不下发该文件或完整字段目录；界面所需的物品信息和进度标记仍会通过接口返回。

**公开仓库不提供源码保密性。** 本目录推送后，任何能访问仓库的人都能复制后端代码。后端部署只能防止“保存网页就能获得独立编辑器”，不能阻止从本仓库复制或重新实现功能。项目继续遵守原 MIT 许可证，见仓库根目录 `LICENSE`。

## 本地启动

需要 Node.js 22 或更高版本，无第三方运行时依赖。须保留整个仓库目录，不能单独复制本文件夹后运行。

```sh
cd 网站
npm start
```

访问 `http://localhost:3000`。服务绑定 `0.0.0.0`，可通过 `PORT` 环境变量更改端口。没有设置访问密码时，知道地址的人均可使用；这只适用于本地测试。

### 启用共享访问密码

通过部署平台的密钥配置设置 `SITE_PASSWORD`，不要把实际密码写入仓库或提交到 Git。访问者在网页“访问密码”中填写该值；浏览器只在页面内存中保存，不写入 localStorage。

Linux / macOS 示例：

```sh
read -s SITE_PASSWORD
export SITE_PASSWORD
npm start
```

PowerShell 可在部署环境中设置 `SITE_PASSWORD` 后执行 `npm start`。正式环境务必启用 HTTPS；否则上传存档和密码可能被窃听。共享密码并不是多用户账号系统，不能代替完整的权限与审计方案。

## 使用

1. 关闭游戏，保留原始备份。
2. 选择备份文件夹，或者同时选择 `progress.sav`、`caption.sav` 和可选的 `option.sav`。文件夹模式自动识别多槽位；手动文件模式仅对应一个独立存档。
3. 编辑生命、魔力、卢比、物品数量、容量、瓶子、钥匙、物品栏、进度标记或语音语言。字段查看器只读。
4. 生成 ZIP 补丁。服务器执行校验和修改，浏览器下载结果。
5. 将时间戳目录内的文件复制到完整备份副本的 `files/` 中；独立存档则复制到存档目录。若包含 `manifest.json`，将其放到备份根目录。补丁不是完整备份。
6. 完成后点击“清除服务器会话”。切换槽位和重置修改均会丢弃未导出的编辑。

与桌面版不同，本版没有直接写入本地文件夹的权限，只提供 ZIP 导出。进度标记和字段名称保留原始 ID；不是游戏剧情的一键解锁工具。

## 数据处理和限制

- 文件上传到服务器内存，不写入磁盘，不输出存档内容、请求体或堆栈日志。
- 会话使用随机 256 位令牌；空闲 15 分钟失效，清理任务每分钟运行一次。明确清除或服务重启后会话失效。删除引用不保证内存立刻被覆写；生产服务器还需自行配置交换分区、崩溃转储和代理日志策略。
- 每次导入最多 16 个有效文件，单文件 2 MiB，总解码数据 12 MiB；JSON 请求体上限 18 MiB。
- 最多 20 个存档会话；内置按连接 IP 每分钟 90 次 API 请求的基础限流，不信任客户端提供的转发 IP。
- 仅显式公开 `public/index.html`、`public/app.js`、`public/style.css`。**不要把仓库根目录设置为静态站点目录。**
- 接口仅允许 JSON POST，校验 Origin，禁止跨站请求，不启用跨域 CORS。
- 浏览器令牌只放在内存中；刷新后不能恢复原会话，旧会话会自动到期。
- 不提供账号、支付、数据库或云端备份功能，也不提供断网编辑。

## 正式部署

这是可运行的初版，不是经过独立安全审计的商业服务。建议单进程部署在 HTTPS 反向代理后，保持请求 Host 与用户访问域名一致；不要缓存 API 或记录请求体。代理上进一步配置请求体大小、上传超时、连接数和按真实来源 IP 限流。多实例部署需要会话亲和或重新设计共享存储；当前内存会话不跨进程同步。

可使用下列 Dockerfile（**构建上下文必须为仓库根目录**）：

```sh
docker build -f 网站/Dockerfile -t oot-website .
# 从受控环境传入 SITE_PASSWORD，不要把密码直接写在命令行参数里。
docker run --rm -p 3000:3000 -e SITE_PASSWORD oot-website
```

GitHub Pages 无法运行 Node.js 后端，不能用于直接部署此版本。

## 测试

```sh
cd 网站
npm test
```

包含原有 9 项存档回归测试及 6 项网站与浏览器辅助逻辑测试：静态文件白名单、导入/切槽/字段查询/导出/清除会话、路径和编码拒绝、跨站拒绝及共享密码。导出测试将 ZIP 中存档字节与原编辑器处理结果进行逐字节比较。

这些测试使用合成存档，不替代真实存档的游戏内验证，也不代表已在所有浏览器上完成手工测试。


## 无法导入时排查

- 访问密码没有默认值。页面会通过 `/api/config` 自动检测：未设置 `SITE_PASSWORD` 时隐藏密码框并明确显示“无需填写”；启用时需由部署管理员提供，不能从接口查询密码。
- 若提示“接口返回了网页而不是 JSON”，说明 `/api/` 收到了静态首页、代理错误页或登录页，而非本应用接口响应。请运行 `cd 网站 && npm start`，访问该 Node.js 服务；不能仅用静态服务器或 GitHub Pages 托管 `public`。
- 使用反向代理时，将 `/` 和 `/api/` 都转发到同一个 Node.js 服务，不要用 SPA 首页回退覆盖 `/api/`。可访问 `/api/config` 检查，应收到带 `service: "oot-sw2se-web"` 的 JSON，而不是 HTML。
- 手动导入必须一次同时选择 `progress.sav` 和 `caption.sav`（Ctrl/Command 多选）；或者直接选择存档文件夹。仅选择 `caption.sav` 无法构成完整存档。
